## 0. 铁律

> 以下为通用骨架，条数与措辞按本团队实际增删；每条只写一句话，不展开。

1. **一个项目一个联络台**：项目文件夹里只有一份「📞联络台.md」，路径写死，是全团队唯一信息源。
2. **入队 / 开工先读联络台**：任何智能体（含新加入者）开始工作前的**第一件事**，必须先读联络台，禁止凭记忆、凭印象干活。
3. **新人先自我介绍再接活**：新智能体入队后，必须先在联络台「团队名册」区写清自己的代号、载体、能力范围与边界，经甲方确认后才能被派单。
4. **只干分内事**：按角色卡派活，不越权、不顺手扩展任务范围。
5. **干完立刻留痕**：每项任务完成后，当场在自己的「📝工作记录.md」追加一条（做了什么 / 结果路径 / 待确认），禁止攒着补写、禁止"口头式做完了"。
6. **派单必入投递箱**：把活交给谁，必须把任务卡文件投递到对方的「📥投递箱/」目录；不能只在联络台登记或在聊天里@人，就当对方已经收到。

## 1.5 智能体工作空间（目录结构）

每个智能体在项目根目录下有且只有一个以自己代号命名的文件夹，内含三件套：

```
项目根目录/
├── 📞联络台.md
└── 智能体们/
    └── <代号>/
        ├── 📥投递箱/      # 别人投来的任务卡，自己开工前从这里取
        ├── 📂工作区/      # 自己干活的中间产物、草稿、临时文件
        └── 📝工作记录.md   # 自己的工作流水账，干完一条当场追加一条
```

规则：

- **投递箱**：别人往里丢任务卡 / 结果文件，自己只负责取；未处理完的投递物不删。
- **工作区私有**：中间产物放这里，不污染项目根目录。
- **工作记录.md 自己写**：每干完一条立刻追加，必须有日期和任务号。
- **跨人接力**：A 干完要交给 B，A 把结果或新任务卡丢进 B 的投递箱；不能只在联络台写一句"已完成，请 B 接手"。

## 2. 项目生命周期

> 以下为通用六步骨架，按团队实际增减。每一步的执行主体写代号，不要写自然语言。

1. **立项**：<谁>接甲方需求 → 确认范围 / 交付物 / 截止 → 建项目文件夹。
2. **开台**：<谁>在项目根目录建「📞联络台.md」（套附录模板），路径写死并告知全员。
3. **拆活**：<谁>把需求拆成任务卡文件，编号 T-01、T-02……
4. **派单**：按角色卡，把任务卡文件**投递到负责人的「📥投递箱/」**，同时在联络台「待办区」登记一行（ID / 任务 / 负责 / 截止 / 状态）。联络台是台账，投递箱是实物，两者都要有。
5. **执行**：执行者开工前先读联络台 → 再从自己投递箱取任务卡 → 在「📂工作区」干活 → 干完**当场在「📝工作记录.md」追加一条** → 若需接力，把结果 / 新任务卡投递到下家投递箱；无需接力则在联络台「交接区」贴交接单。
6. **验收**：<谁>按验收标准核验 → 通过归档；不通过附问题清单，重新投递回执行者投递箱。

## 7. 任务状态词表

所有智能体统一用以下状态，禁止自造词：

| 状态   | 含义                       | 谁负责推进      |
| ---- | ------------------------ | ---------- |
| 待办   | 已投递到投递箱、未开工              | 负责人        |
| 进行   | 正在干                      | 负责人        |
| 待验收  | 已写交接单、等验收               | 验收人        |
| 已交付  | 验收通过、归档                  | —          |
| 退回   | 验收不通过、打回修订               | 负责人        |
| 挂起   | 被外部条件阻塞，暂停推进             | 派单人决定何时恢复 |

## 8. 文件命名与优先级

**任务卡文件**：`T-XX-任务简称.md`（XX 两位数字，如 `T-03-官网首页改版.md`），直接丢进对方投递箱。

**交付物**：禁止用"最终版""真最终版""改了又改""final2"这类名字；按项目自己的规范命名，但必须见名知意。

**优先级**：

- **P0**：阻塞他人、必须当天处理
- **P1**：本周期交付
- **P2**：有空再做

---

## 9. 异常与退出

- **投递箱积压**：任务在投递箱超过 <X> 天未被取走 → 派单人提醒一次；提醒后仍不动 → 上报甲方裁决。
- **智能体临时缺席**：先把自己手上进行中的任务在联络台标「挂起」，注明阻塞原因；回来第一件事读联络台 + 自己投递箱。
- **智能体退出项目**：先清空投递箱（未处理任务退回派单人）→ 工作记录.md 归档 → 工作区中间产物由甲方决定保留或删除。
- **甲方不在线**：P1 / P2 任务可继续推进；凡涉及删文件、改配置、对外发消息、动账号云盘的动作，一律等甲方在线再做，不自行决定。
