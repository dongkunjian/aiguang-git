## 2026-10-16  故障处置：公网 1033 隧道断 + 根因定位（看门狗其实从未生效）

- **现象**：甲方截图报 Cloudflare **Error 1033 / Cloudflare Tunnel error**，域名 gogit.dongkunjian.ccwu.cc 打不开
- **第一层定位**：本地 8321 无监听、cloudflared 进程 **0 个**、看门狗进程 **0 个** —— 不是隧道掉线，是三个进程全没了。原因是它们都由当前终端会话 `Start-Process` 派生，会话/终端重启时进程树被一并回收
- **首次恢复**：改用 WMI `Win32_Process.Create` 拉起 `server.py` 与 `cloudflared`（父进程变成 `WmiPrvSE.exe`，脱离会话进程树，不再被回收），公网恢复 HTTP 200
- **深挖（本轮关键收获）**：重拉看门狗时发现它 2 秒即退出 → 逐层排查定为**编码问题**：`.cloudflared/start.ps1` 存的是「UTF-8 **无 BOM**」，而 PowerShell 5.1 对无 BOM 的 UTF-8 脚本会按系统 GBK(936) 解码，脚本里的中文路径 `F:\软件开发\爱逛GIT` 直接变乱码 → `Start-Process -WorkingDirectory $root` 与 cloudflared 的 `--config` 路径全错，又被 `$ErrorActionPreference="SilentlyContinue"` 吞掉 → **静默失败**。也就是说**第 5 批写的看门狗从上线起就没真正工作过**
- **连带发现**：启动文件夹里的 `aiguang-git.bat` 是 UTF-8 编码，而 cmd.exe 按 OEM 代码页 936 逐行读取批处理 → 里面的中文路径同样乱码，**开机自启也是坏的**
- **修复**：① `start.ps1` 重写并存为 **UTF-8 带 BOM**，文件头写明该约束与踩坑原因，避免后人再犯；② `aiguang-git.bat` 转存为 **GBK / ANSI(936)**；③ 新增 `.cloudflared/watchdog.log` 事件日志（只在真正动手时写一行，不刷屏）
- **验证**：看门狗日志出现「看门狗启动（PID 6696）」；随后**主动杀掉 cloudflared 做断线演练**，10 秒后被自动拉起（日志「拉起 cloudflared」），公网复测 HTTP 200 —— 自愈链路首次被证实真的可用
- **环境红线（写给下一个接手的人）**：这个项目路径含中文，凡是含该路径的 **`.ps1` 必须存 UTF-8 带 BOM**、**`.bat` 必须存 GBK(936)**，否则一律静默失效；后台常驻进程请用 WMI `Win32_Process.Create` 派生，别用 `Start-Process`
- **当前状态**：server 8321 在听 / cloudflared 1 个 / 看门狗 PID 6696 存活（WMI 派生，跨会话存活）
